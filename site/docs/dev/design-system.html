Design system and tokens

ModScrim looks like a practice ground, not a gaming app: wall green and chalk for the field, a hand-hung scoreboard for results, and a coach's whistle for the mark. This page explains the tokens, the contrast gate that protects them and how to use the brand kit. The complete rules are brand/DESIGN.md, written for people and for AI coding agents.

The idea

  • The practice field. Wall green is the ground, chalk is the type and the pitch markings.
  • The manual scoreboard. Results sit on dark green boards with hung number plates. Numbers are big and condensed; leading zeros are blank plates.
  • The whistle. The mark is a coach's whistle with chat's typing dots inside. Whistle orange is the one action colour.
  • Practice is always labelled. Card yellow marks anything that is practice.

Where the tokens live

FileRole
design/tokens.css, tokens.json, palette.jsonGenerated by the bundled colour skill from the brand colours. Do not hand-edit; re-run the skill
design/tokens.override.cssEvery ModScrim deviation from the generated baseline: semantic roles mapped onto the brand primitives, measured hover fills, the action border
site/css/tokens.css, site/css/tokens.override.cssCopies for the website, because Cloudflare Pages publishes only site/
app/src/main.tsxImports the two design/ files for the app

Semantic variables such as --color-bg, --color-text and --color-action are what components use. Colour comes from tokens only.

The contrast gate

Contrast follows WCAG 2.2: body text 4.5:1, large text 3:1 and meaningful non-text 3:1. Measured pairs from the brand file include chalk on wall green at 10.6:1, moss on chalk at 5.7:1, deep green on whistle orange at 5.4:1 (button labels) and deep green on card yellow at 10.7:1.

Whistle orange as a fill on chalk is only 2.5:1, below the 3:1 non-text bar. That is the one documented exemption, and it holds only because an orange control is identified by its label and its border, not by the fill alone. Two scripts protect it:

CommandWhat it enforces
npm run contrast:checkThe generated tokens pass the validator with no exemptions, and the shipped palette fails on exactly the documented pairs (orange on chalk, orange on white), no more and no fewer
npm run lint:tokensAny rule that fills itself with the action colour must also declare --color-action-border or --color-border-strong
npm run site:tokens:checksite/css/tokens*.css still match design/ (run npm run site:tokens to copy)
npm run site:coloursEvery colour hand-written in site/ is a token or listed in brand/DESIGN.md

All four run in CI. To change a colour, change the override file and re-run the gate; do not widen the exemption without recording why.

The README banner, docs/assets/banner.svg, is built from the horizontal-tagline-reverse lockup and the reverse mark with the brand colours.

Logo rules. Keep at least one mark-height of clear space. Below 48 px use the small cut (no ring, no window); at 16 px drop the dots too.

Do and do not

  • Do label every screen that shows attack text as practice, in card yellow.
  • Do keep one orange button per view; second actions are outline buttons.
  • Do write plain, specific copy from the moderator's side.
  • Do not use Twitch purple, the Twitch logo, or wording that suggests Twitch made or endorses ModScrim.
  • Do not render attack text anywhere outside a labelled practice chat, including marketing screenshots.
  • Do not put orange text on chalk (use #B33D00), add gradients or glitch effects, or fade sections in on scroll. Motion answers actions, and prefers-reduced-motion turns it off.
